# 输入适配与取证

## 1. DOCX 只读检查

在 Skill 目录执行：

```bash
python scripts/inspect_docx.py "<待检稿.docx>" --out "<证据目录>/docx"
```

本机有 Tesseract 且需要识别图片文字时：

```bash
python scripts/inspect_docx.py "<待检稿.docx>" --out "<证据目录>/docx" --ocr
```

没有 Tesseract 时脚本不会失败，只在 `warnings` 写 `OCR_UNAVAILABLE`。此时必须人工查看 `media/` 全部图片。

必读产出：

- `inspection.json`：结构化总表与 `flags`
- `body.txt`：正文段落和表格文本
- `tables.json`：表格行列
- `media/`：全部内嵌图片
- `image_references`：每次图片引用的 story part、段落、媒体文件、相邻图注与 alt text；同一媒体在正文和页眉重复引用时逐次保留上下文

至少核对：

1. 正文段落、表格、SDT、文本框、脚注尾注和图片出现顺序。
2. 每张图片的 `next_paragraph_text` 与 alt text，识别「增程版」「纯电版」「Max」「旗舰」等图注。
3. `external_links`、`external_images` 与 `field_codes`，重点找 `clickx`、`dspmnt`、`javascript:`、无引号 HYPERLINK、外链/VML 图片；表格单元格同样检查。
4. `tracked_changes`、`comments`、`hidden_text`、`headers_footers`、`other_story_parts`、`core_properties`。
5. `has_macros`、`has_activex`、`has_ole`、`has_embedded_objects`；发布件默认不带宏、ActiveX、OLE 和嵌入对象。

脚本拒绝含 DTD/实体声明的 XML（含 UTF-16/UTF-32），限制 ZIP 成员数、总解压量和单个 XML/媒体文件大小；document、header、footer、footnotes、endnotes、comments 的全部图片关系（含未引用关系）都会校验，引用媒体超限、关系 ID 缺失或内部媒体缺失时硬失败。关系目标支持百分号编码，图片部件按 OPC 内容类型识别；未引用的合法图片仍进入媒体清单。OCR 超时记录 `OCR_TIMEOUT` 并继续，不中断结构检查。不得修改原 DOCX；清理发布件时使用另存副本。

## 2. 公开参数页捕获

仅在用户明确授权联网时执行：

```bash
python scripts/capture_public_page.py "<公开参数页URL>" --out "<证据目录>/page" --fetch-scripts --scan-api
```

脚本保存：

- `page.html`：原始页面
- `visible_text.txt`：去除脚本后的可见文字
- `disclaimers.json`：页面声明与免责语
- `metadata.json`：请求 URL、最终 URL、读取时间、状态、内容类型、SHA-256
- `scripts.json`：同源脚本清单、各自读取时间、最终 URL 与 SHA-256
- `api_candidates.json`：脚本中发现的 API 路径候选

安全边界：默认只允许全局可路由地址，拒绝回环、私网、共享地址、链路本地和保留地址；连接后复核实际对端 IP，逐跳校验重定向；脚本与 API 重定向后仍须同源。`--allow-loopback` 仅用于本机测试，生产核查不得开启。

动态页面只有 HTML 外壳时，从同源脚本或浏览器只读网络面板定位真实数据接口，再执行：

```bash
python scripts/capture_public_page.py "<公开参数页URL>" --out "<证据目录>/page" --api-url "<同源API完整URL>"
```

API URL 必须来自页面本身或用户明确提供，不得猜测；必须与页面同源，且每一跳重定向都不得跨源，跨源目标会在请求发出前阻断。保存 `api.raw.json` 原始字节，`api.json` 仅作为解析视图；非 JSON 响应保存 `api.raw.bin`。页面、每个脚本和 API 分别记录 UTC 读取时间、最终 URL 与 SHA-256。网页脚本只作静态扫描，不执行。页面非 2xx 保留证据但退出 2；API/脚本非 2xx 不保存为成功证据并退出 1；部分抓取失败时退出码为 1，URL 边界或页面抓取失败时退出码为 2。

来源固定写：

- 来源类型：`其他（公开媒体参数页，非官方）`
- 核验状态：`用户提供，未独立核验`；主动检索所得写 `待复校`
- 页面声明：逐条保留「仅供参考」「以官方为准」等原文
- 读取时间：使用 `metadata.json` 的 UTC 时间，不写成页面发布日期

## 3. 汽车垂媒 getParamConf 规范化

从已捕获的同源 API JSON 执行：

```bash
python scripts/normalize_auto_media_config.py "<params.json>" --out "<证据目录>/config" --target-energy pure_ev --source-url "<参数页URL>" --fetched-at "<UTC读取时间>"
```

`--target-energy` 可选：

- `pure_ev`：纯电
- `range_extender`：增程
- `hybrid`：插混
- `unknown`：未知

输出：

- `normalized.json`：车系、来源、版型与关键参数；指定目标能源类型时，每版型含 `usable_for_target`
- `facts.json`：12 列材料信息卡，只输出目标能源类型可用的版型事实
- `gate.json`：能源类型硬门
- `matrix.md`：目标能源类型可用版型的矩阵；不可信文本已转义
- `issues.json`：问题分类、内容风险与证据充分度

单项与多项 `sublist` 均保留页面原始 `●` / `○` 标记及有序 `{name, value}` 配对：`normalized.json` 的每个版型含 `selection_details`，`facts.json` 在字段值后追加标记及含义。`●` 只表示页面标配标记，`○` 只表示页面选配/可选标记且待核；均不得据此替代厂商正式配置表。敏感值在全部规范化产物前统一脱敏，来源文件只保留 basename；`unknown` 目标或仅含未知能源类型的来源一律阻断。

判读：

- `blocked`：目标能源类型不在来源中，写「版型错配」，不可发。
- `allowed_with_limits`：能源类型匹配，但仍须核对具体版型、市场、日期和官方配置表。
- `not_checked`：未明确目标能源类型，先补目标范围。

禁止：

- 用增程版参数证明纯电版，或用纯电版参数证明增程版。
- 用 Max、Ultra、旗舰等高配数据外推全系。
- 把页面「未列出」写成「没有」。
- 把公开媒体参数页写成厂商正式配置表。

## 4. 证据命名与归档

每次核查使用独立证据目录，至少保留：

```text
evidence/
  docx/inspection.json
  docx/media/
  page/metadata.json
  page/page.html
  page/api.raw.json
  page/api.json
  config/normalized.json
  config/facts.json
  config/gate.json
  config/matrix.md
```

文件名不含真实客户、手机号、身份证号或未公开价格。证据目录只保存必要材料；未经用户授权不得上传或外发。
